标注格式: PASCAL VOC XML

  - 包含 <size> (宽高)、<object> (类别+边界框)

1.3 NEU-CLS 与 NEU-DET 图像对比
--------------------------------
图像数量:
  - NEU-CLS: 1800 张
  - NEU-DET 原始: 1770 张
  - 理论上 NEU-DET 应该也是 1800 张（与 NEU-CLS 同图像，外加标注）

类别-编号对交集: 1770 对完全匹配
  - 两个数据集的图像内容相同，只是 NEU-DET 少了 30 张
  - NEU-CLS 有但 NEU-DET 没有的 30 张，恰好是上面列出的缺失编号

命名格式差异:
  - NEU-CLS: 4位零填充 (crazing_0001.jpg)
  - NEU-DET: 无零填充 (crazing_1.jpg)
  - 编号含义相同，只是格式不同

颜色模式差异:
  - NEU-CLS: L (单通道灰度)
  - NEU-DET: RGB (三通道，但 R=G=B，是伪彩色)
  - 像素内容一致，只是存储方式不同

二、标注格式与转换
================================================================================

2.1 原始标注格式
----------------
格式: PASCAL VOC XML
位置: data/raw/NEU-DET/ANNOTATIONS/
文件数: 1770 个 .xml 文件

XML 结构样例 (crazing_1.xml):
  <annotation>
    <filename>crazing_1.jpg</filename>
    <size>
      <width>200</width><height>200</height><depth>1</depth>
    </size>
    <object>
      <name>crazing</name>
      <bndbox><xmin>2</xmin><ymin>2</ymin><xmax>193</xmax><ymax>194</ymax></bndbox>
    </object>
  </annotation>

2.2 转换脚本
------------
脚本位置: scripts/convert_neudet.py
功能: 将 VOC XML 标注转换为 YOLO txt 格式
转换逻辑:
  - 读取 XML 中的 bndbox (xmin, ymin, xmax, ymax)
  - 转换为归一化中心坐标 (x_center, y_center, width, height)
  - 类别名 -> 类别索引映射 (按 CLASS_NAMES 列表顺序)

类别映射:
  0 -> crazing
  1 -> inclusion
  2 -> patches
  3 -> pitted_surface
  4 -> rolled-in_scale
  5 -> scratches

类别名处理: 脚本中有容错逻辑（小写化、空格转下划线、模糊匹配），
但实际 NEU-DET 的 XML 中类别名与 CLASS_NAMES 完全一致。

YOLO 标注样例 (crazing_1.txt):
  0 0.487500 0.490000 0.955000 0.960000
  格式: class_id x_center y_center width height (均归一化到 [0,1])

2.3 数据划分方式
----------------
convert_neudet.py 默认划分比例:
  train: 70%, val: 20%, test: 10%
随机种子: seed=42

注意: 实际项目中存在多个不同划分的 YOLO 格式数据集（见第三节）。

  yolo_format/test  与 neudet_official_yolo/test  交集: 33 张

【严重问题】如果用 yolo_format 的训练集训练，再用 neudet_official_yolo 的 val/test
评估，会有大量训练数据泄露到验证/测试集中，导致结果虚高。

3.4 neudet_official_yolo 多出 30 张图像来源不明
------------------------------------------------
原始 NEU-DET 只有 1770 张图像，但 neudet_official_yolo 有 1800 张。
多出的 30 张恰好是原始数据中缺失的那些编号：
  - crazing: 151, 153, 166, 240, 241 (5张)
  - inclusion: 161, 169, 195, 263 (4张)
  - patches: 28, 63, 128, 151, 274 (5张)
  - pitted_surface: 18, 64, 110, 125, 175, 249 (6张)
  - rolled-in_scale: 14, 80, 138, 176, 216 (5张)
  - scratches: 86, 195, 264, 286, 300 (5张)

推测: neudet_official_yolo 数据来自 NEU-CLS（1800张完整数据），
然后用某种方式（可能是 NEU-CLS 图像 + 官方 GitHub 下载的标注）生成了标签。
这 30 张图像的标注框来源需要进一步验证。

标注框数量对比:
  原始 NEU-DET XML:    4126 个标注框
  neudet_official_yolo: 4189 个标注框
  差异: +63 个（来自多出的 30 张图像）

================================================================================
七、发现的全部不一致问题汇总
================================================================================

【严重级别】
-----------
1. NEU-DET 原始数据只有 1770 张，但 neudet_official_yolo 有 1800 张，
   多出的 30 张图像来源不明，其标注框的真实性存疑。
   多出的标注框共 63 个。

2. 项目中存在 5 个 YOLO 格式数据集，划分各不相同，且存在大量跨数据集
   split 重叠。如果混淆使用会导致数据泄露，结果不可信。
   例如: yolo_format/train 与 neudet_official_yolo/val 重叠 188 张。

3. 88.97% 是 test 集上的结果，但报告和文档中未明确标注是 test 集。
   容易与 results.csv 中的 val 集指标混淆。

【重要级别】
-----------
4. 存在 5 个 YOLO 格式数据集：
   yolo_format, neudet_official_yolo, neudet_yolo_real,
   neudet_yolo_gan_mixed, yolo_gan_mixed
   划分比例、图像数量、命名格式各不相同，容易混淆。

5. GAN 增强模型 (yolov8s_neudet_gan) 缺少 args.yaml 和 results.csv，
   无法验证训练配置、数据集、超参数等关键信息，可复现性差。

6. NEU-CLS 图像是灰度图 (mode=L)，NEU-DET 图像是伪彩色 RGB，
   虽然像素值相同，但存储格式不同，可能导致预处理行为差异。

7. baseline 的 val 集最佳 mAP50=77.41%，但 test 集 mAP50=76.35%，
   两者不一致，分别来自不同的数据集划分。

8. baseline 模型 (yolov8s_baseline-2) 训练用 neudet_official_yolo，
   而 configs/yolo_config.yaml 中配置的是 data/processed/yolo_format，
   配置文件与实际训练使用的数据集不一致。

【一般级别】
-----------
9. baseline-2 配置 epochs=200，实际训练 162 个 epoch
   (early stopping 触发, patience=30)

10. 不同数据集划分比例不同：
    yolo_format: 70/20/10
    neudet_official_yolo: 70/15/15

11. data.yaml 路径设置不一致：
    neudet_official_yolo: path: '.' (相对路径)
    yolo_format: path 为绝对路径

12. 文件名命名格式不统一：
    NEU-CLS / yolo_format: 4位零填充 (crazing_0001.jpg)
    NEU-DET / neudet_official_yolo: 无零填充 (crazing_1.jpg)

13. NEU-DET.zip 压缩包仍保留在项目根目录，data/raw/NEU-DET/ 已解压，
    存在冗余。
